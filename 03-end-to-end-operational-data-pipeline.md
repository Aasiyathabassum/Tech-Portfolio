# 🔗 End-to-End Operational Data Pipeline with Power Platform & Cloud Analytics  
**Role:** Data Engineer 
**Focus:** Shopfloor data capture, Power Platform automation, hybrid cloud ingestion, analytics enablement & digital standards  

---

## 🧭 Project Overview

This project focused on designing and delivering an **end-to-end operational data pipeline** to eliminate fragmented, manually recorded shopfloor data and replace it with a **connected, automated, and analytics-ready digital data flow**.

The solution established a **digital thread** from:
- Technician data entry on the shopfloor  
→ Automated ingestion  
→ Secure hybrid cloud storage  
→ Advanced analytics and visualization  

In parallel, I led a **digital infrastructure review and literature-driven standards definition** to establish **minimum future-state digital requirements** for data retention, interoperability, traceability, and security.

## 🔄 End-to-End Data Pipeline Flow

### 1️⃣  Data Capture (Power App)
- Technicians enter:
  - Part ID
  - Process selection
  - Start/end timestamps
  - Key process parameters
- Role-based forms ensure:
  - Data quality
  - Mandatory field enforcement

---

### 2️⃣ Ingestion & Automation (SharePoint + Power Automate)
- Submission creates a new record in **SharePoint**
- This automatically triggers a **Power Automate workflow**
- Workflow performs:
  - Time standardization
  - Field normalization
  - JSON structuring

---

### 3️⃣ Secure API Transmission
- Structured data is transmitted via:
  - Secure HTTP actions
  - API Gateway endpoints
- Data is pushed into:
  - Hybrid cloud storage layers
  - On-premise or cloud staging (based on use case)

---

### 4️⃣ Cloud Storage & Analytics Enablement
- Data is stored in scalable cloud object storage
- Consumed by:
  - Analytics platforms
  - Dashboarding tools
  - Machine learning pipelines
- Enables:
  - Real-time monitoring
  - Historical trend analysis
  - Predictive quality insights

## 📦 Data Model Strategy (High Level)

Defined support for three standardized data domains:
- **Process Data** (time-series production parameters)
- **Simulation Data** (model outputs & structured datasets)
- **Metrology Data** (quality & measurement outputs)

Each domain aligned to:
- Structured formats (CSV / JSON / XML)
- Metadata-driven governance
- ISO-aligned data modelling principles
